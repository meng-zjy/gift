# 《我们的小小世界》项目计划

更新日期：2026-11-09

阶段：v0.7.0，三层小屋、露天庭院、星空阳台、照片展板、成就长廊与本地内容管理
目标仓库：https://github.com/meng-zjy/gift

## 1. 项目背景与目标

制作一份送给彼此喜欢的人的生日纪念礼物，并让它在生日之后继续更新。采用俯视角网页像素探索游戏：玩家操控像素小人，在小屋及周边场景中发现双方的回忆。

内容包含照片、出游经历、日记、视频、双方说过的话、生日、食物喜好、礼物与关系里程碑。记录应同时呈现双方的表达，既有“我对她”，也有“她对我”。

核心体验：走进一间属于两个人的小屋，通过探索家具与房间重温经历，并在生日场景中收到祝福。

### 已确认方向

- 生日礼物定位，可以明确表达喜欢。
- 两个像素角色，开场动画、对白、小屋探索和成就长廊。
- 厨房承载食物喜好，书桌承载日记，庭院承载出游记录。
- 支持持续添加内容，后续可以增加房间。
- 她喜欢莫奈、梵高、小蛋糕、草莓、芒果和甜食。
- 用户后续自行配置服务器与域名。
- 主场景参考《星露谷物语》的俯视角 2D 像素表现；按用户要求采用平面移动，不引入 Y 轴纵深模拟。
- 角色外观后续由用户提供图片，前期使用明确的临时角色。
- 每次迭代必须提供可运行、可体验的最小 Demo。
- 所有剧情都提供跳过与回看，支持临时中断后返回。

### 本轮规划边界

规划讨论阶段只更新文档。用户随后确认开始开发，并授权自主推进、运行验证，到可玩里程碑再试玩调整；当前交付范围为一楼客厅和厨房、二楼过道与卧室、负一楼成就长廊、独立画作、剧情阅读，以及日记、话语、相册、生活里程碑的本地管理与备份。庭院、阳台、昼夜、视频、生日演出及服务端继续按后续里程碑交付。用户时间宽裕，可在功能完成后再补充真实素材。

### 当前基础

旧普通网页原型已保留在 `archive/website-prototype/`。当前为 Vite + React + Phaser 小屋原型，支持客厅厨房往返、故事暂停跳过回看与本地阅读进度，已具备本地手账台与照片选择，尚无服务器同步与登录能力。

2026-11-05 通过 GitHub 读取目标仓库时，默认分支为 `main`，根目录仅有 `README.md`。此为初期读取记录；当前已建立 Git 关联，main 与里程碑标签同步到远程仓库。

原网页中的生日、经历和对白均为示例，不得作为真实内容直接发布。

## 2. 游戏流程

```text
打开链接 → 点击开始并选择声音 → 开场动画与短笺
    → 两个角色在门口相遇 → 进入小屋自由探索
    → 通过家具阅读回忆、查看照片视频、发现彩蛋
    → 前往生日场景 → 读信、看视频、许愿
    → 保存进度，之后继续回来探索新内容
```

- 开场可跳过、可重播；音乐通过用户操作开启，并提供静音。
- 用户已同意单角色操作方案，另一个角色固定在屋内并可对话。Demo 0 使用静态待机姿态，待机动画后续补充；首版不加入自动跟随。
- 电脑支持方向键/WASD、互动键；手机提供触控移动和互动按钮。
- 生日礼物始终有直接入口，不要求大量任务或收集才能看到。
- 阅读窗口打开时暂停角色移动；关闭后回到探索。
- 提供回忆目录，方便直接重看读过的内容。

### 2.1 视角与移动约定

- 游戏主场景为俯视角 2D 平面，角色在屏幕 X/Y 平面上下左右移动。
- 屏幕 Y 坐标只表示地图上的位置，不表示高度或远近；不引入 Z 轴、透视缩放、跳跃或纵深物理。
- 地板、家具、人物和前景采用明确的固定图层；初版不引入按角色 Y 坐标动态排序的纵深遮挡机制，地图布局配合这一规则。
- 《星露谷物语》作为像素尺度、俯视室内和移动手感参考；素材自行制作或使用允许使用的资源。
- 生日蛋糕可以使用单独的 3D 演出窗口，不改变主游戏的二维移动规则。

### 2.2 两种角色方案与推荐

| 方案                     | 体验                                                   | 工作量与维护                                                       | 本计划建议     |
| ------------------------ | ------------------------------------------------------ | ------------------------------------------------------------------ | -------------- |
| 双角色切换               | 分别看到双方对白、心情或专属物件                       | 需要角色切换、双份位置状态、视角文案及交互检查；游玩时间也可能增加 | 保留为后续增强 |
| 单角色操作，另一角色固定 | 操作简单；另一人一直在小屋中，可以待机、对话和参与演出 | 更快完成核心体验，内容不必重复制作                                 | 已确认并实现   |

双角色切换指单人切换操控，不等同于双人联机。若后续采用，普通回忆默认双方共享，只为少量重要场景增加不同视角，避免同一段故事必须重复读两遍。

预留角色 ID、当前操控角色、对白视角与可选内容可见范围。首版不提前开发第二套流程或角色专属任务；另一人的想法可以先通过对话、信件和日记呈现。

### 2.3 剧情跳过、中断与回看

根据试玩反馈，静态文字不自动推进，取消手动“暂停阅读”；仍保留离开、分段恢复和跳过。视频、自动演出后续实现时提供播放暂停。当前各物件专属展示见 [v0.3.0 改进记录](./visual-experience.md)。

适用于开场、人物剧情、回忆演出、生日动画和结尾，不限于首页开场。

- 从剧情开始即显示“跳过”；文字支持立即显示，视频支持暂停、拖动和关闭。
- 区分“暂停”“跳过本段”和“退出剧情”，避免误操作直接结束全部内容。
- 切到后台、窗口失焦或主动暂停时，保存当前段落；返回后由玩家点击继续。
- 开场和文字剧情可按段落恢复；视频尽量恢复播放时间，无法精确恢复时返回当前段落并明确提示。
- 回忆目录保留已触发剧情，即使跳过也能找到；提供从头回看与继续上次位置。
- 阅读状态区分未打开、已打开、已读完；跳过不伪装成读完。
- 跳过后恢复到安全的探索状态，关闭遮罩、解锁输入并停止演出音效。必要的场景状态通过统一完成出口处理。
- 重播不会重复发放成就、重复解锁或覆盖正常探索位置；关闭回看后返回进入前的位置。
- 打开回看目录时，明确区分已触发故事和未开放内容，避免提前暴露惊喜。

### 2.4 首次进入与可调整的展示方案

初步提供“要一起回忆一下吗？”窗口。用户提出的“否按钮无法按下”可做成一次轻松彩蛋：按钮短暂躲开或变成一句俏皮回应，然后出现稳定可点击的选择。

始终保留“直接进小屋”和关闭入口；跳过剧情的按钮保持正常可用。关闭恶作剧效果、使用触屏或键盘时，也能顺畅进入游戏。具体文案和动作先由设计给出，后续按用户反馈调整。

生日房间先提供可运行的 2D 蛋糕、点蜡烛与祝福，再独立迭代为可旋转或带镜头动画的 3D 蛋糕演出。3D 方案属于候选效果，需单独 Demo 验证手机性能、加载和表现；加载失败时保留二维蛋糕与信件入口，跳过和回看规则一致。

## 4. 可扩展架构

### 4.1 房间由配置驱动

每个房间独立定义：稳定 ID、名称、地图资源、出生点、出口、碰撞区域、互动点、背景音乐、主题和可选开放条件。

房间通过出口关联目标房间与出生点，不把整栋小屋写成固定尺寸的大地图。支持后续添加二楼、画室、温室、海边等场景。

通用场景加载器处理地图加载、角色进入、碰撞、互动点注册、切换与资源释放。避免为每个房间复制移动和碰撞逻辑。

### 4.2 通用互动注册机制

| 类型     | 能力                   | 使用例子       |
| -------- | ---------------------- | -------------- |
| 阅读文字 | 展示日记、信件与短句   | 书桌、信封     |
| 查看相册 | 展示照片、说明和排序   | 相框、旅行地图 |
| 播放影音 | 展示视频或音乐         | 电视、唱片机   |
| 人物对话 | 按配置播放对白         | 陪伴角色       |
| 展示收藏 | 展示喜好、礼物与票根   | 冰箱、收藏柜   |
| 前往场景 | 切换房间与进入位置     | 门、楼梯       |
| 触发事件 | 启动演出或更新探索状态 | 蜡烛、彩蛋     |

使用现有互动新增房间时，主要添加地图、素材与配置；全新玩法需要增加对应互动处理器。第一版不承诺任意新玩法都能无代码完成。

配置必须校验 ID 唯一性、目标房间与内容引用、出生点有效性、互动类型和开放条件。无效配置在开发或发布检查时明确报错。

### 4.3 内容与地图分离

回忆独立保存，家具引用内容 ID。同一段“第一次约会”可以出现在庭院长椅、客厅相框和成就长廊中，正文只维护一份。

每条内容记录作者或说话人、涉及人物、发生日期、正文、媒体、草稿/发布状态、创建与修改时间。未知日期允许留空，不用虚构日期补齐。

### 4.4 存档兼容

- 使用稳定的房间、内容、物件和成就 ID，不通过数组下标识别。
- 保存当前房间、有效位置、已读内容、探索事件、成就与存档版本。
- 更新地图后检查位置是否仍可通行；失效时回到房间安全出生点。
- 房间移除或尚不可用时回到客厅。
- 新增内容与房间不清空已有进度；存档结构变化提供迁移。
- 场景按需加载，共享资源复用，切换时释放房间专属资源。
- 存档预留当前操控角色、已触发剧情、阅读状态、剧情段落与必要的播放进度；回看状态与正常探索存档分开处理。

### 4.5 编辑能力分级

第一版通过地图文件和配置扩展房间，通过后台维护内容与已有互动点的内容绑定。

后续增加房间模板和互动点可视化摆放工具。完整地图编辑器不作为生日版本的前置条件。

## 5. 成就设计

### 生活里程碑

由管理者记录真实经历，如第一次约会、第一次旅行、第一次收到她的礼物、第一次一起过生日。保存真实发生日期、说明和关联回忆，可隐藏尚未准备公开的里程碑。

### 探索成就

根据游戏事件自动解锁，如第一次进入小屋、打开冰箱、读完一封信、找到芒果彩蛋、参观全部已开放房间。

- 解锁操作可安全重复执行，不重复发奖或弹窗。
- 成就定义与玩家解锁记录分离。
- 新增房间不撤销已获得的“完成探索”成就，可用新的版本成就鼓励再次探索。
- 普通探索成就不得阻断生日信和生日视频的访问。

## 6. 视觉与声音

统一像素比例、人物规格和家具表现，再使用不同场景的配色与气氛区分主题。

- 庭院：莫奈式蓝紫花园、睡莲、池塘和柔和倒影。
- 夜空：梵高式深蓝、旋转星光与金黄强调。
- 室内：木色、暖灯和生活用品。
- 彩蛋：草莓、芒果、小蛋糕和喜欢的画，作为真实可互动的物件。
- 角色：用户后续提供图片，再确定双方发型、眼镜、常穿衣服及像素形象；前期用可替换的占位精灵。
- 照片、视频、长文章使用清晰的阅读窗口，保证手机阅读体验。
- 提供音量、静音、对白立即显示、跳过演出和减少动态效果选项。

## 7. 技术建议与模块边界

以下为总体方案。Demo 0 已使用 Phaser、React、TypeScript 和 Vite；Tiled、服务端与数据库尚未引入。

| 部分           | 建议                  | 职责                         |
| -------------- | --------------------- | ---------------------------- |
| 游戏           | Phaser 3 + TypeScript | 角色、场景、碰撞、动画与音效 |
| 阅读和管理界面 | React + TypeScript    | 相册、日记、表单、内容管理   |
| 工程           | Vite                  | 开发、打包                   |
| 地图           | Tiled                 | 图层、碰撞、出口和互动区域   |
| 服务端         | Node.js + TypeScript  | 登录、内容、上传、发布和存档 |
| 数据库         | SQLite 起步           | 单台服务器的结构化存储       |
| 媒体           | 服务器独立目录        | 照片视频保存、备份与迁移     |

如确认 3D 蛋糕，单独评估 Three.js 等演出实现，按需加载；不因此更换主游戏引擎。

建议目录：

```text
docs/                   产品、设计与交付文档
apps/web/src/game/      游戏运行、输入、场景、互动与音效
apps/web/src/ui/        阅读窗口与游戏菜单
apps/web/src/admin/     管理后台
apps/server/            内容、媒体与存档接口
packages/shared/        共享类型、配置结构与校验
content/                演示内容与房间配置
assets/                 可进入仓库的像素素材与音效
```

真实照片、视频、日记与运行数据通过后台存入独立数据目录，不进入公开代码仓库。

模块依赖：游戏通过内容接口读取记录，通过统一事件通知成就和存档模块；后台复用同一套内容结构。第一阶段可用本地适配器，正式版本接服务端，避免将 localStorage 调用散布在各个房间。

## 8. 管理与数据能力

### 管理者

添加、编辑、隐藏和发布内容；上传照片视频；管理日期、喜好、对白、生活成就；将记录绑定到互动点；维护开场与生日信。支持草稿预览，发布后游戏可读取新内容。

### 游玩者

探索已发布空间、阅读已发布内容、保存个人探索进度。以后是否开放她直接写日记和共同编辑，作为单独的权限需求确认。

### 核心数据

- 人物：双方身份、展示名与头像。
- 房间配置：地图、出入口、主题、开放状态与互动点。
- 内容：日记、回忆、信件、话语、偏好及相关人物。
- 媒体：文件类型、存储位置、说明、排序与关联内容。
- 成就定义：生活或探索类型、条件、关联回忆。
- 游玩进度：已读记录、探索事件、已解锁成就与存档版本。
- 网站设置：生日、开场、音乐与生日演出内容。

服务端职责包括内容查询与发布、媒体上传与读取、进度保存与恢复、管理身份校验。所有管理写入都由服务端检查；读取接口不返回未发布内容。上传失败可重试，保存失败明确提示并保留编辑草稿。

## 9. 最小可交付 Demo 与验收

### 9.1 每次迭代的交付要求

- 从第一个开发版本起即可启动和体验，不以仅有目录、接口或大量未接通功能作为交付。
- 每次只增加一条可完整体验的流程，沿用上一个能运行的版本。
- 每个 Demo 附带启动命令、访问地址、操作说明、此次新增内容、已知限制和建议体验步骤。
- 暂无真实素材时使用明确的演示内容；前几个 Demo 不依赖服务器和正式人物图片。
- 每次交付执行适用的类型检查、构建和关键交互验证，并如实记录手机实机是否已验证。
- 用户体验后的调整纳入下一次小迭代，不必等整阶段完成后才看到效果。
- 表中阶段可以拆成多个小 Demo，每一个开发交付版本仍须独立可运行。

| 阶段                   | 交付                                                   | 验收标准                                                           |
| ---------------------- | ------------------------------------------------------ | ------------------------------------------------------------------ |
| Demo 0：能走进房子     | 一间客厅、一个可操控角色、一个固定角色、碰撞和一条回忆 | 按说明即可启动；键盘与触控可移动；打开和关闭回忆后均能继续玩       |
